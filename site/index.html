Overview

ENAMEL-Extended is a from-scratch Python reimplementation of ENAMEL, the code-efficiency benchmark introduced by Qiu, Zeng, Ezick, Lott & Tong (ICLR 2025). ENAMEL measures the efficiency of LLM-generated code — not just correctness — by comparing runtime against expert reference solutions on adversarial test inputs.

The headline finding: models that look strong on pass@k are far from expert level on eff@k. GPT-4 reaches pass@1 = 0.831 but only eff@1 = 0.454. This reimplementation reproduces the metric, builds a resumable measurement harness with bootstrap confidence intervals, and investigates the published claims.

Key contribution: We measure the q-distribution across levels (§2.2 of the open questions) — showing that level 3 carries 71% of the score's sensitivity while levels 1–2 carry 60% of the weight but minimal discrimination.

Methodology

Efficiency Score

For each problem, code is run against 4 levels of test cases (8 + 4 + 4 + 4 cases). The per-level score is: 

f = (T_i − max_m t[i,j,l,m]) / (T_i − max_m t*[i,l,m])

where T_i = α · maxl,m t*i,l,m with α = 2. Levels are combined by hardness-weighted mean with h = (3, 3, 4).

eff@k Estimator

The Rao–Blackwellized estimator over n ≥ k samples, using binomial weights over order statistics (Algorithm 1 from the paper). Theorem 1 proves unbiasedness and a variance bound of (k/n)·Var[max].

Robust Timing

Each test case runs R = 6 repeats, aggregated by the Hodges–Lehmann estimator for robustness to outliers. Candidates are executed in a sandboxed subprocess with resource limits.

Statistical Rigor

Every reported score carries a bootstrap confidence interval (10,000 resamples). No comparison is claimed without a pairwise test. The α-sweep and h-sweep are reported alongside the headline.
